Maestro and Appium run their iOS tests through the Apple tools `xcrun`, `xcodebuild` and `xcode-select`. `sim-remote` provides stand-ins for these tools. With the stand-ins on your `PATH`, a stock Maestro or Appium installation runs its tests on a hosted simulator. This also works on Linux without Xcode.

## Install the stand-ins

`sim-remote install-shims` writes the stand-ins to a cache directory and prints the shell code that puts them on your `PATH`. Evaluate the output in your shell:

```bash
eval "$(sim-remote install-shims)"
```

In fish, pipe the output to `source`:

```fish
sim-remote install-shims --shell fish | source
```

Run the command again after you update `sim-remote`. The command rewrites the files to match the binary.

## Maestro

Log in, install the stand-ins, and run Maestro with the UDID of a hosted simulator:

```bash
sim-remote login
eval "$(sim-remote install-shims)"
maestro --udid 6C3F1B2A-9D4E-4A77-B1F0-2E8C5D9A0413 test flow.yaml
```

Maestro installs its test runner on the simulator one time per session and starts it through the `xcodebuild` stand-in. The stand-in opens a forward tunnel to the runner, so Maestro finds it on the local port that it expects.

## Appium

Start the stock Appium server with the XCUITest driver. A session needs the `appium:isHeadless` capability and the UDID of a hosted simulator:

```bash
sim-remote login
eval "$(sim-remote install-shims)"
appium &
```

```json
{
  "platformName": "iOS",
  "appium:automationName": "XCUITest",
  "appium:udid": "6C3F1B2A-9D4E-4A77-B1F0-2E8C5D9A0413",
  "appium:isHeadless": true
}
```

The hosted machine ships a prebuilt WebDriverAgent. The `xcodebuild` stand-in installs it on the simulator instead of a local build.

## Limits

- Each fetch of the view hierarchy takes several seconds on a large app. Increase the step timeouts of flows that you wrote for a local simulator.
- The startup of the test runner must fit in the driver timeout. Increase the timeout on a slow network.
- Permission changes go through `simctl privacy`. Notifications, health and Face ID permissions are not available.
- `maestro start-device`, the `setProxy` flow command and crash report artifacts are not supported.
- Appium ignores the capabilities that change the WebDriverAgent build or its bind address.

The [Maestro and Appium reference](/docs/cloud/reference/test-drivers) lists the prerequisites, the options and the known limits. The [CLI reference](/docs/cloud/reference/cli) lists all commands.
